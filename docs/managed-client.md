# Managed VanaDreams client

VanaDreams Install and Patch use the published 30260904_1 manifest (September game and PlayOnline plus the published Chapter I entry). They never extract into a user-selected existing game. The chosen folder establishes the parent/name; the installed copy is a versioned sibling. The installer hashes each archive, builds a per-file inventory from the verified contents with published overlay ordering, and verifies that inventory before atomically renaming the candidate. Chapter I and official payload go in the candidate's private asset tree. The active path is saved only after verification; the previous folder stays in place. Windows registration is not changed by Install or Patch.

Migration copies only USER from the previous recognized VanaDreams install, not base files, DLLs, game tables, or DAT overlay folders. Launcher profiles and settings stay in their existing launcher/Ashita administrative directories. The canonical launch uses just the managed Chapter I and gameplay text overlays, not old aesthetic overlays. They remain unchanged on disk. If installation is cancelled, it does not activate or alter the old copy; verified downloads are reusable. A completed generation whose settings activation was interrupted can be recognized and reused after a full verification.

VanaDreams Play validates the complete generation against the published manifest fingerprint and the files on disk. A drifted copy must be replaced with Patch; a separate retail client is not a fallback. This does not change any server version lock. Retail/capture requires its own registered client and uses no managed overlay.

Local published fixture test (Windows): place the served manifest as manifest.json beneath a private directory and cache each verified archive under downloads/managed-client/<computed manifest key>. Set VD_MANAGED_TEST_FIXTURE to that private directory. Run the PublishedFixture test category to exercise full extraction, Chapter I launch profile preparation, drift and repeatable repair without launching the game. A live scene run is a separate check.
